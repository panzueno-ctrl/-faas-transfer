============================================================
  API ENDPOINTS
============================================================

  TRANSFERT
  ─────────────────────────────────────────────────────────
  POST   /upload            → Reçoit le fichier, stocke dans Supabase,
                              retourne un id unique + lien + code 6 chiffres

  GET    /download/:id      → Récupère le fichier depuis Supabase,
                              déclenche le téléchargement

  DELETE /expire/:id        → Supprime le fichier de Supabase
                              et les métadonnées de la DB

  CONVERSION
  ─────────────────────────────────────────────────────────
  POST   /convert/word-to-pdf     → Word (.docx/.doc) → PDF        ✅ V1
  POST   /convert/pdf-to-image    → PDF → JPG / PNG                ⬜ V1
  POST   /convert/image-to-pdf    → JPG / PNG → PDF                ⬜ V1
  POST   /convert/pdf-to-pptx     → PDF → PowerPoint               ⬜ V1
  POST   /convert/pages-to-pdf    → .pages → PDF (Apple)           ⬜ V2
  POST   /convert/key-to-pdf      → .key → PDF (Apple Keynote)     ⬜ V2


============================================================
  BASE DE DONNÉES — Supabase
============================================================

  Table: transfers
  ┌─────────────┬────────────────────────────────────────┐
  │ Colonne     │ Description                            │
  ├─────────────┼────────────────────────────────────────┤
  │ id          │ Identifiant unique du transfert        │
  │ file_name   │ Nom original du fichier                │
  │ file_url    │ URL du fichier dans Supabase Storage   │
  │ expires_at  │ Date d'expiration du lien              │
  │ downloaded  │ Boolean — a-t-il été téléchargé ?      │
  │ created_at  │ Date de création                       │
  └─────────────┴────────────────────────────────────────┘


============================================================
  FLUX COMPLET END-TO-END
============================================================

  TRANSFERT
  ─────────────────────────────────────────────────────────
  1. Sender ouvre l'app → sélectionne un fichier par catégorie
         ↓
  2. App propose conversion optionnelle avant envoi
         ↓
  3. App envoie POST /upload au serveur Express
         ↓
  4. Serveur stocke le fichier dans Supabase Storage
         ↓
  5. Serveur crée une entrée dans la table transfers
         ↓
  6. Serveur retourne l'id unique à l'app
         ↓
  7. App affiche trois options :
       ├── QR code        → "Scannez si vous êtes proches"
       ├── Lien           → "Copiez si vous êtes éloignés"
       └── Code 6 chiffres → "Entrez le code dans l'app"
         ↓
  8. Receiver scanne / clique le lien / entre le code
         ↓
  9. Navigateur ou app → GET /download/:id
         ↓
  10. Serveur récupère le fichier depuis Supabase → téléchargement
         ↓
  11. Fichier marqué downloaded = true → suppression après 10s

  CONVERSION
  ─────────────────────────────────────────────────────────
  1. Utilisateur sélectionne un fichier dans l'onglet Convertir
         ↓
  2. App propose les conversions disponibles selon le type du fichier
         ↓
  3. App envoie POST /convert/[type] au serveur
         ↓
  4. Serveur convertit via LibreOffice
         ↓
  5. Serveur retourne le fichier converti
         ↓
  6. App propose de télécharger ou d'envoyer directement

============================================================

Parfait. Voilà ce qu'on veut faire et comment on va s'y prendre.

Ce qu'on veut faire aujourd'hui
Construire le serveur Express qui peut :

Recevoir un fichier depuis une requête HTTP

Retourner un id unique

Étape 4 → Connecter Supabase
Étape 5 → Créer le serveur Express de base
Étape 6 → Créer l'endpoint /upload
Étape 7 → Créer l'endpoint /download/:id
Étape 8 → Tester avec Thunder Client ou Postman

Problème 1 — Expo Go

 Expo Go sur ton téléphone était en SDK 57 mais ton projet était en SDK 56.
 Les deux versions ne sont pas compatibles. 
 Et le réseau WSL ne permettait pas à ton téléphone d'accéder directement au serveur Expo.

Problème 2 — Railway Node.js

Railway utilisait par défaut Node.js 18 pour faire tourner ton serveur Express. 
Mais le package @supabase/supabase-js dans sa version récente nécessite Node.js 20 minimum
 — il utilise des APIs WebSocket natives qui n'existent pas dans Node.js 18.
En ajoutant "engines": { "node": ">=20.0.0" } dans package.json,
 on a forcé Railway à utiliser Node.js 20 — et là tout a fonctionné.

Résumé simple :
Railway (Node 18) + Supabase récent = incompatible ❌
Railway (Node 20) + Supabase récent = compatible  ✅
C'est un problème classique en déploiement 
— l'environnement de production est différent de l'environnement de développement.
 Sur ton PC tu avais Node.js 24 donc pas de problème, 
 mais Railway avait une version plus ancienne par défaut.
